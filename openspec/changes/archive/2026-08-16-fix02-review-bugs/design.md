## Context

全量代码 review 后确认 4 个功能缺陷（进度恢复错位、空文件清库、收藏变更队列过期、完成态按钮不可见）与 1 处调试代码遗留。其中空文件行为与现行 `wordbook` spec 的"导入空文件"场景（清空原词条）冲突，本变更同时修订该 spec 场景。进度恢复缺陷的根因：`currentWordIndex` 的语义依赖 `currentWordOrder`（随机播放的乱序、记忆反馈后续轮次过滤出的"未反馈子集"），而原实现恢复时重建顺序后直接套用旧索引，指向错误单词。

## Goals / Non-Goals

**Goals:**

- 进度恢复在任何播放顺序（顺序 / 随机 / 未反馈子集轮次）下都还原到保存时正在展示的单词
- 空文件导入不再造成数据丢失
- 收藏夹单词本启用时，收藏增删后背记队列实时反映收藏内容
- 完成状态"重新开始"按钮可见、悬停显示、移出隐藏
- 移除生产环境调试日志
- 全部修改通过单元测试验证

**Non-Goals:**

- 不修复 `deleteEntry` / `updateEntry` / 重新导入普通词库后队列过期问题（同类问题，另行立项）
- 不改变 Core Data 模型
- 不处理全屏自动隐藏检测失效问题（需先讨论检测策略）
- 不做多语种发音协议抽象

## Decisions

### Decision 1: 进度顺序持久化 — wordId 序列（已确认）

**方案：** `saveProgress` 将当前轮次 `currentWordOrder` 对应的 wordId 列表一并写入 UserDefaults；`restoreProgress` 将 wordId 映射回 Section 内索引，校验无重复且全部存在后才套用保存的单词索引，否则清除进度从头开始。

**替代方案：**
- 保存 `[Int]` 索引数组 — 实现更简单，但词库重新导入后索引指向错位单词且无法察觉
- 不存顺序、恢复时重算 — 随机播放恢复必然错位，等于未修复

**代价：** 旧版本进度缺少顺序数据，升级后首次启动一次性从头开始（旧数据本就无法可靠恢复）。

### Decision 2: 收藏变更响应 — 按需重建并尽量恢复（已确认）

**方案：** 引擎监听 `.favoritesDidChange`，仅在收藏夹单词本已启用且处于播放状态时响应：保存当前进度 → 重建队列 → 通过 `restoreProgress` 尽量回到原位置（当前单词仍存在时停留原位，已被移出收藏则从头开始）。收藏夹未启用（默认状态）时完全忽略，不重置进度。

**替代方案：**
- 无条件重启 — 实现最简，但收藏夹未启用的用户（大多数）每次点收藏都丢进度，不可接受
- 静默原地重建、保持当前显示 — 体验最好，但当前词被移出收藏的边界处理复杂度高

**已知代价：** 收藏夹启用时切换收藏，当前单词会重新展示一次（含自动重读发音）。

### Decision 3: 完成态操作入口 — 移除"重新开始"按钮（用户裁决）

**方案（用户确认）：** 完成状态下不显示任何操作按钮。右键菜单本就提供"重新开始"入口（见 floating-window spec「右键菜单」需求），窗口内按钮属重复入口，整体移除 `restartButton` 及其回调链路；`activeButtons()` 在完成态返回空集合，悬停/移出逻辑统一无操作。

**历史过程：** 初版方案为修复按钮使其可显示（按钮此前未加入视图层级，从未可见）。人工验证阶段用户裁决改为移除。

**替代方案：**
- 修复并保留按钮 — 已否决（与右键菜单重复）
- 保留按钮但仅悬停显示 — 已否决（同上）

### Decision 4: 空文件处理 — 解析层抛 `emptyFile`（已确认，行为变更）

**方案：** `parse` 在无任何有效词条时抛 `ImportError.emptyFile`，复用现有错误提示链路。代码中 `emptyFile` 枚举本已声明但从未使用，本变更使其生效，并修订 spec 中"清空原词条"的旧场景。

### Decision 5: 收藏词条稳定标识 — 使用 favoriteId 作为 wordId（人工验证发现的回归，已修复）

**根因：** `favoriteToWordEntry` 原实现每次转换生成临时 `UUID().uuidString` 作为 wordId。收藏夹单词本启用时，`buildQueue` 每次执行（含重启后）都产生全新标识，保存的播放顺序与 feedbackSet 中的 wordId 全部无法映射，进度被整体重置——"重启恢复到确切单词"在收藏夹启用场景下必然失败。

**方案：** wordId 改用 `Favorite.favoriteId`（创建收藏时持久化、跨会话稳定、天然唯一），进度保存/恢复与反馈集合匹配随之稳定。新增回归测试 `testRestoreWithFavoritesWordbookEnabled`（修复前已验证失败、修复后通过）。

**替代方案：**
- 用 sourceWord 作标识 — 删除后重新收藏同词会误命中历史进度；且同词多义场景不唯一
- 收藏时固定生成并回写 wordId 到 wordDetail — 需改动 JSON 结构，favoriteId 已满足，无必要

## Risks / Trade-offs

| 风险 | 缓解措施 |
|------|---------|
| 旧版本进度升级后失效，用户感知"从头开始" | 一次性代价且旧恢复行为本身指向错误单词；spec 明确记录 |
| 收藏夹启用时进度恢复失效（人工验证发现） | wordId 改用持久化 favoriteId；新增收藏夹启用场景回归测试 |
| 空文件行为变更与用户预期不符（原预期清空） | spec 同步修订，错误提示明确"文件内容为空" |
| 收藏切换瞬间当前单词重显 + 重读发音 | 仅收藏夹启用时发生；换来队列内容实时正确 |
| `.favoritesDidChange` 在后台线程发送导致引擎在非主线程操作 Timer/UI | 收藏夹同步在 `DispatchQueue.main.async` 后发送，`toggleFavorite` 本身在主线程 |
| wordId 映射遇到重复 ID（数据异常） | 构建映射时保留首个索引，列表含重复则校验失败回退 |
