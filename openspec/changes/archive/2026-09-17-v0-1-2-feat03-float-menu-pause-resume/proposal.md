## Why

悬浮窗切词完全由固定时长 Timer 驱动，用户没有"暂时挂起背诵"的手段：临时被会议/演示打断、或想停下来专注看当前词时，只能靠把鼠标停在窗口内维持悬停暂停（离开即恢复），或直接退出应用。已有的暂停能力只覆盖"鼠标在窗内"与"动效预览"两个瞬时来源，缺少一个由用户主动发起、跨鼠标位置持续生效的暂停态。

右键菜单是悬浮窗唯一的全局控制入口（打开设置 / 退出程序 / 已学完时重新开始），在此处增加"暂停背记 / 继续背记"符合产品"极简、低干扰、高自定义"的定位，改动面也最小。

## What Changes

### 1. 用户暂停（第三个暂停来源，复用现有暂停通道）

新增用户主动暂停，与既有悬停暂停、预览暂停并列，任一存在即冻结切词计时：

- **冻结语义**：暂停时记录当前单词剩余停留时长并停表，当前词原地保持展示；解除后按剩余时长继续（不整段重计）
- **复用引擎既有暂停标志**，不新增第二套计时状态机——由此自动继承三条已验收的边界行为：暂停中手动切词保持暂停、引擎重启保持暂停、`stayDuration` 热更新在暂停态仅更新记录值
- **发音同步挂起**：进入暂停时停止正在播放的语音并屏蔽后续自动播报，解除时恢复（与全屏静音路径同样的成对写法）
- **暂停期间交互不锁死**：hover 仍浮现按钮，`♡` / `▶` 可用，`✓` / `✗` 仍可手动切词（切完继续冻结）

### 2. 右键菜单项

菜单在"打开设置"之前插入暂停项，文案随状态翻转：`暂停背记` ⇄ `继续背记`。"已学完"状态下不出现该项（该状态本已无计时）。

### 3. 状态交叉处理

- **窗口隐藏（全屏自动隐藏 / 显隐切换）**：手动暂停原样保留，不做代偿恢复、不加视觉提示（区别于悬停暂停的强制恢复）；恢复显示后窗口静止属预期行为，唯一入口为右键菜单的"继续背记"
- **与"重新开始"共存**：点击"重新开始"时一并清除用户暂停，避免重启后的首个单词是冻住的
- **不跨重启保留**：暂停为纯内存临时态，应用重启后正常开始背记（进度照常恢复）

## Capabilities

### New Capabilities

无（扩展现有能力）。

### Modified Capabilities

- `floating-window` — 右键菜单需求扩展（新增暂停/继续项、已学完状态下不出现、隐藏态不恢复）
- `recite-engine` — 新增"用户暂停背记"需求（冻结语义、发音挂起、与悬停/预览暂停的合成规则、重启路径不悬空）

## Impact

**受影响文件：**

| 文件 | 变更类型 | 说明 |
|------|----------|------|
| `Features/FloatingWindow/FloatWindowController.swift` | 修改 | 新增 `isUserPauseRequested` 第三暂停源，经 `setUserPaused` 独立下发（不并入 hover/preview 的 OR 合成）；菜单项构建与 tag 分发；暂停时停止在播语音 + 挂起发音，解除时按静音状态决定是否恢复；`restart` 路径先清除用户暂停；显示路径不再无条件解除挂起 |
| `Services/ReciteEngine.swift` | 修改 | `isHoverPaused` 语义化为 `isTransientPaused`，新增 `isUserPaused` / `setUserPaused`；计时副作用改由合并值的迁移边沿驱动（`applyPauseState`），解除时缺失剩余记录按整段时长兜底，避免重启后悬空 |
| `Shared/Constants.swift` | 修改 | `FloatMenuTag` 新增 `pauseResume` |
| `Resources/Localizable.xcstrings` | 修改 | 新增 `float.menu.pause` / `float.menu.resume`（zh / en） |
| `HoverWordTests/` | 新增 | 用户暂停与悬停/预览暂停的合成、暂停中引擎重启后解除、暂停中手动切词、发音挂起恢复 |

**兼容性：**

- 悬停暂停、预览暂停既有行为与全部既有 Scenario 不变，仅新增一个并列来源
- 无设置开关、无新增持久化键，默认行为与现状一致（不暂停）
- 不涉及任何语种判断，词书无关设计保持

**已知取舍：** 窗口恢复显示后若仍处于用户暂停，悬浮窗无任何可见提示，仅右键菜单文案体现"继续背记"——用户可能误以为窗口卡住。已在 spec 中写成显式 Scenario 而非留白。
